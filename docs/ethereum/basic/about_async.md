# 以太坊為什麼不能平行處理交易?

<br>

---

<br>

以太坊無法實現並行交易處理的根本原因，我理解是這樣：


以太坊需要產生新 block 時，會由一個共識機制決定的單一節點站出來，去以太坊公共交易池中蒐集一批交易 (以新區塊 gas limit 為區塊大小上限，抓取一批交易數量)，交易池中的交易資料都是以排序好的．

然後這個產塊節點會使用當前世界樹 (MPT) 的副本嘗試一個一個的執行交易．每一筆交易的執行都會改變世界樹．當有交易執行失敗便跳過(偽造交易，或餘額不足的情況)．

<br>

當該產塊節點完成一個區塊所有的交易演算後，會算出當前世界樹根 (state root) 並跟著交易資料以及產塊節點地址等訊息一併打包封入 Block 中．透過廣播傳遞給自己以及其他節點．

<br>

收到這個 block 的節點們，則需要各自對 Block 進行驗證，包括交易根，收據根，狀態根．還需要取出交易資料，跟當時產塊節點做驗算時的行為一樣．也取出狀態樹進行 snapshot -> 驗證交易(VRS, nonce, balance) ->  ->執行交易 -> Commit State -> 持久化 Block 與 State

這其中的步驟基本上無法找出使用非同步的機會．交易必續同步執行的原因也是因為交易必須保證有序性進行（非同步無法保證有序性）．

<br>

如果交易是無序的．可能會發生某一包交易在 A 節點驗證執行是：

```
1. 小王 + 100 ETH
2. 小王 + 100 ETH
3. 小王 - 200 ETH
```

在 B 節點驗證執行是：

```
3. 小王 -200 ETH (失敗)
2. 小王+ 100 ETH
1. 小王+ 100 ETH
```

這會導致不同節點無法對同一個 block 進行驗證與狀態同步．
