🔍 EXTENSION 節點：為什麼需要？什麼時候用？

💡 EXTENSION 節點的核心作用

EXTENSION 節點的唯一目的：路徑壓縮 (Path Compression)
將多個只有單一子節點的節點壓縮成一個節點，大幅提升空間效率和查詢性能。

🎯 簡單理解

想像你要從家走到學校，路上有很多個只有一條路的路口：

  • 沒有路徑壓縮：每個路口都要停下來確認方向
  • 有路徑壓縮：直接標示「往學校方向直走 5 個路口」

EXTENSION 節點就是這個「直走 5 個路口」的指示牌！

❌ 沒有 EXTENSION 節點會怎樣？

範例：存儲三個相似的鍵

"cat" = [6,3,6,1,7,4]
"car" = [6,3,6,1,7,2]
"card" = [6,3,6,1,7,2,6,4]

公共前綴：[6,3,6,1,7] (長度 5)

🚫 沒有 EXTENSION 節點

BRANCH (root) ├─[6] BRANCH ├─[3] BRANCH ├─[6] BRANCH ├─[1] BRANCH ├─[7] BRANCH ├─[2] LEAF [] = "car" └─[4] LEAF [] = "cat" 深度：6 層 節點數：6 個 BRANCH + 2 個 LEAF = 8 個節點
問題：
  • 浪費大量空間
  • 查詢需要 6 次跳轉
  • 每個中間節點都要存儲

✅ 有 EXTENSION 節點

EXTENSION [6,3,6,1,7] └─BRANCH ├─[2] LEAF [] = "car" └─[4] LEAF [] = "cat" 深度：3 層 節點數：1 個 EXTENSION + 1 個 BRANCH + 2 個 LEAF = 4 個節點
優勢：
  • 節省 50% 的節點數量
  • 查詢只需 2 次跳轉
  • 路徑信息集中存儲

⏰ 什麼時候需要 EXTENSION 節點？

判斷規則：
條件：公共前綴長度 > 0
if commonLen > 0 { 創建 EXTENSION 節點 }

💻 EXTENSION 創建的程式邏輯

func insertIntoLeaf(leaf *MPTNode, path []byte, value []byte) (*MPTNode, error) { commonLen := commonPrefixLen(leaf.Path, path) // 1. 完全匹配：不需要 EXTENSION if commonLen == len(leaf.Path) && commonLen == len(path) { leaf.Value = value return leaf, nil } // 2. 創建分支節點處理分歧 branch := createBranchNode(leaf, path, value, commonLen) // 3. 關鍵判斷：是否需要 EXTENSION if commonLen > 0 { // 有公共前綴 → 創建 EXTENSION 節點 return &MPTNode{ NodeType: EXTENSION, Path: path[:commonLen], // 公共前綴 Child: branch, // 指向分支節點 Dirty: true, }, nil } // 4. 沒有公共前綴 → 直接返回分支節點 return branch, nil }

🔍 詳細步驟分析

步驟 1：計算公共前綴
commonLen = commonPrefixLen([6,3,6,1,7,4], [6,3,6,1,7,2]) = 5
步驟 2：創建分支節點處理分歧點
分歧發生在索引 5，值為 4 和 2
步驟 3：檢查是否需要 EXTENSION
commonLen = 5 > 0 → 需要 EXTENSION
步驟 4：創建 EXTENSION 節點
路徑：[6,3,6,1,7]，子節點：分支節點

📈 性能數據對比

鍵的數量 平均公共前綴長度 沒有 EXTENSION 有 EXTENSION 節省比例
100 個地址 8 nibbles 800 個節點 200 個節點 75%

真實影響：
  • 存儲空間：EXTENSION 節點可以節省 75-90% 的存儲空間
  • 查詢速度：減少節點跳轉次數，提升查詢效率
  • 網路傳輸：Merkle proof 更短，網路傳輸更快
  • 記憶體使用：減少節點數量，降低記憶體壓力

🌍 EXTENSION 在以太坊中的實際應用

📱 以太坊地址的特性

以太坊地址格式：0x + 40 個十六進制字符 範例地址： 0x742F35C8663F25849B3B3678a9b17dC2E15F5BE7 0x742F35C8663F25849B3B3678a9b17dC2E15F5BE8 0x742F35C8663F25849B3B3678a9b17dC2E15F5BE9 公共前綴：742F35C8663F25849B3B3678a9b17dC2E15F5BE (39 個字符) → 轉換為 nibbles 有 39 個公共 nibbles！
EXTENSION 節點的關鍵作用：
  • 處理相似地址的存儲優化
  • 合約地址通常有相似前綴
  • 交易哈希也經常有公共前綴
  • 大幅減少以太坊狀態樹的大小

🔗 實際場景範例

傳統方式

每個 nibble 一個節點 深度：40 層 查詢：40 次跳轉 存儲：大量中間節點

MPT 方式

EXTENSION 壓縮公共前綴 深度：3-5 層 查詢：2-4 次跳轉 存儲：最小化節點數

🎯 總結：EXTENSION 節點的必要性

1. 什麼時候需要？
當有公共前綴時（commonLen > 0）
2. 為什麼需要？
路徑壓縮，大幅提升空間和時間效率
3. 如何判斷？
計算兩個路徑的公共前綴長度
4. 實際效果？
節省 75-90% 的存儲空間，提升查詢速度
💡 關鍵理解：
EXTENSION 節點不是可有可無的優化，而是 MPT 能夠高效處理大量相似鍵值對的核心機制。 沒有 EXTENSION 節點，MPT 就退化成了效率極低的普通 Trie 樹！
